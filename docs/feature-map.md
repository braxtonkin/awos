# Feature map

Every user-facing feature, how to reach it, and where its code lives. Update this file in the same PR as the feature (rule C3 in [AGENTS.md](../AGENTS.md)).

| Feature | What it does | How to reach it | Code |
| --- | --- | --- | --- |
| Code change workflow | Declares Specify, Implement, Verify, and Land, the steps a ticket goes through in one repository. Verify's review says whether the behavior is fixed, still wrong, or could not be checked. Land declares the verdicts the engine will observe on the pull request: a red check, requested changes, and a required approval. | A routine saved with the workflow `code-change`. No screen yet. `npm run verify -- code-change` checks the declaration against the task model and runs each step's judge. | `features/code-change/`, `shared/workflow.ts`, `shared/review.ts` |
| Task steps, gates, and person actions | Decides a task's next step from its workflow when an attempt ends or a person acts, stops at the routine version's last step, holds a task at each gate until a person approves the review, and waits for answers when a step needs input, at most 3 times in a row. A task parks with an instruction when a cap is reached. Stop, Retry, Approve, Send back with a note, and each answer are recorded as the person's actions, and a decision on a review the task no longer waits on is refused. | No screen or engine loop yet. `act` and `advance` in `features/tasks/advance.ts`. `npm run verify -- tasks-sim` runs every behavior against Postgres with a copy of Code change. | `features/tasks/`, `db/migrations/20260924000000_workflow_kinds.sql`, `db/migrations/20260924000100_workflows.sql` |
| Engine start check | Refuses to start while a routine uses a workflow the engine was not given, and names each such routine and the workflows it can use. | `node services/engine/main.ts` with `DATABASE_URL` set. | `services/engine/`, `features/tasks/start.ts` |
| Reaper | Releases every attempt whose lease has expired within one interval, in one statement that checks the lease, and logs one line per release with the task key and how long the lease had been expired. On start, and after a pass fails or Postgres answers later than one interval, it first gives each live attempt a lease of at least one period from then. A pass that took longer than one interval rolls back. On SIGTERM it finishes its pass and the engine exits 0. | `node services/engine/main.ts` with `DATABASE_URL`, and optionally `LEASE_MS` (60000), `REAPER_EVERY_MS` (30000), `DATABASE_POOL_SIZE` (10), and `DATABASE_CONNECT_TIMEOUT_MS` (10000). `npm run verify -- engine-start` runs the engine process. `npm run verify -- tasks-sim --profile crashes`, `db-pause`, or `two-engines` runs the same loop in the simulator, and `npm run verify -- reaper-perf` times it. | `features/tasks/reaper.ts`, `shared/loop.ts`, `services/engine/main.ts` |
| Stored credentials | Stores each person's GitHub token and Codex login sealed with AES-256-GCM. The dashboard's database role can replace a credential but never read one back, and each replacement records who made it and when. The engine opens a credential for the person a run acts as. | No screen yet. `npm run verify -- credentials` runs every behavior against Postgres. | `features/credentials/`, `db/migrations/20260923232000_credential_kinds.sql`, `db/migrations/20260923232100_credentials.sql` |
