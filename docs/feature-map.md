| End-to-end test | Makes a run branch, `e2e/run-<id>`, from the sandbox folder alone, files an SBX ticket on it, lets a driver take it, and checks each step against the system that owns it: ticket filed, task recorded, plan posted, draft pull request, evidence posted, merged, and clean. The plan and evidence steps read AutoWorker's own comments. Clean waits until the clean check finds nothing left for the ticket: an owed outbox action, a gap or repeat in an attempt's stored events, a fragment left after its item completed, a stored item that does not replay through `shared/items.ts`, an item or turn still in progress in an attempt that passed, a Job or Secret labeled for one of the task's attempts, an unstopped Verify environment, or a branch the record names (an attempt's branch or the pull request's branch) still on GitHub. At clean it checks AutoWorker's record: one done task, attempts in step order with their verdicts, each run as the expected person and on gpt-6-luna, Verify's environment started and stopped once, Verify's evidence failing first and passing second, and replay matching the stored items one for one. It checks the ticket ended in the routine's end status, plants a Secret for a finished attempt and passes only when the clean check names it, and counts the pull requests and repeated comments. Then it posts a report on the ticket, with the timeline, each attempt's duration and agent input tokens, AutoWorker's overhead (time to clean less the agent's turn time), and links to the ticket, the pull request, the merge commit, and both CI runs, and reads the report back. The `autoworker` driver, the default, runs the real engine with Jobs on kind. The `throwaway` driver runs the real agent on gpt-6-luna. The `identity` driver implements the ticket as a function that returns its input, so the acceptance test must fail. | Outbox | Performs each external action a task owes, such as a comment, a pull request, or a merge. A state change owes its actions through `enqueue`, which takes only the branded transaction from `shared/transaction.ts`, so a row commits with the state that owes it or not at all. A task with an unsettled row is not ready, so its next step cannot be claimed. A performer claims one row at a time with a lease, in order within each task, drops a row whose task was stopped, looks for the row's marker first when the target cannot catch a duplicate, and checks its lease right before the call, whose deadline is the lease's end less a margin. A failed call keeps its claim until the lease runs out, and each lapse counts as a try. At the cap the row fails and its task waits for a person with the row's last error. A task already waiting on a review keeps it, and the review's note names the failure. Retry owes the failed rows again with their tries reset. | Agent steps | Runs each agent step of a task as one attempt. The engine's `worker` loop resolves who the attempt runs as, claims it on its own branch `autoworker/<key>-attempt-<n>` from the lost attempt's last push, the task's branch, or the repository's branch, starts Verify's environment, builds the prompt from the step's core prompt, the routine's instructions, any Retry or Send back note and answers, the goal, the fast test command, the setup command, the step's input, one line per named skill, and a summary of a lost attempt, and launches the Job with the step's review as the turn's output schema. The Job runs the bridge, and after the turn it pushes the workspace when its tree differs from the start commit's, or for Verify it runs the reproduction as the `reproduce` user, with a scrubbed environment and time and output limits, and posts the runs as a `reproduced` line. Then it posts its end line. The engine records each push on the attempt, and in the end line's transaction reads the final message, stores the step's evidence, applies the verdict, and owes the step's actions. One pass at a time launches an attempt, under a Postgres advisory lock on its id.
